# 文章内的分步图解

在 GitHub Issue 的 Markdown 中，用 `steps` 容器包裹准备好的多张图片：

```markdown
::: steps 快速排序

![选择基准值](https://example.com/step-1.png)

![划分左右区间](https://example.com/step-2.png)

![递归处理子区间](https://example.com/step-3.png)

:::
```

- `steps` 后面的整行是标题，标题可省略，不需要引号。
- 每行一张普通 Markdown 图片，按书写顺序展示；图片之间可以留空行。
- 图片描述作为替代文本和当前步骤说明，可以留空，不会用文件名补齐。
- 容器内只支持图片，不支持段落、列表、代码、嵌套容器或播放参数。
- 必须以独占一行的 `:::` 结束。空容器、不完整容器和包含其他内容的容器按普通 Markdown 展示。

无标题的最简写法：

```markdown
::: steps

![](https://example.com/step-1.png)

![](https://example.com/step-2.png)

:::
```

## 阅读与素材

点击图片或「下一步」前进，「上一步」回看。焦点位于组件内时，也可以使用左右方向键。所有切换方式均支持循环：最后一步前进回到第一步，第一步回退到最后一步。不自动播放，多组图解的进度互不影响。只有一张图片时，图片及切换按钮不可切换。

整组标题以较小字号显示在左上方，图片描述作为当前步骤标题显示在它下面，当前步数放在步骤标题同一行的右侧。底部保留上一步、下一步，不显示进度圆点，不提供全屏或放大按钮。

图片以 16:9 的区域完整展示，不裁剪；建议同组图片使用相同比例、画布大小及元素位置，切换时更连贯。切换时保留整组所需的高度，避免正文跳动。没有图片描述时标题留空，步数仍显示在该行右侧。

禁用 JavaScript 时顺序展示全部图片，隐藏切换控件。普通文章图片仍使用原有的图片预览，分步图解中的图片只用于切换步骤。

这是博客的自定义语法；其他 Markdown 阅读器可能直接显示容器标记，图片仍采用普通 Markdown 写法。
